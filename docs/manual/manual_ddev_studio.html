01 Visión General, Filosofía de Diseño y Arquitectura

DDEV Studio es una estación de trabajo gráfica de nivel empresarial construida en Python 3 y GTK+ 3 (PyGObject) concebida para transformar radicalmente la experiencia de desarrollo local con Docker y DDEV en entornos GNU/Linux (Ubuntu, Debian, Fedora, Arch Linux).

Arquitectura del Sistema & Separación de Responsabilidades (SoC)
El codebase está estructurado siguiendo una rigurosa separación modular:
  • Capa de UI (ddev_studio/ui/): Totalmente desacoplada ("tonta"). Maneja widgets GTK3, estilos CSS nativos y eventos de usuario. Nunca ejecuta comandos de bloqueo.
  • Lógica de Negocio (ddev_studio/core/): Componentes puros ("ciegos" de la interfaz gráfica). Encapsulan detección de tecnologías, cálculo de métricas Docker, generación de plantillas CI/CD y comunicación HTTP REST con Ollama.
  • Patrón Estrategia de Recetas (ddev_studio/recipes/): Automatización desatendida del ciclo de vida para 11 tecnologías distintas con inyección de proxies reversos Nginx y daemons de segundo plano.

Principios de Ingeniería Aplicados

  • Threading No Bloqueante: Cada comando shell (DDEV, Docker, Composer, Drush) se despacha en un hilo daemon secundario (threading.Thread) y canaliza eventos a GTK de manera segura exclusivamente mediante GLib.idle_add().
  • Sanitización Estricta de Procesos: Cero inyecciones de comandos shell arbitrarios. Todas las invocaciones externas utilizan listas vectorizadas o sanitización con shlex.quote.
  • Cero Rutas Hardcodeadas: Portabilidad total sin dependencia del usuario del sistema mediante DEFAULT_SITES_DIR y variables de entorno estándar.

02 Módulo "Mis Proyectos": Catálogo y Gestión en Vivo

La vista central de la aplicación proporciona una vista unificada de todos los proyectos DDEV registrados en la máquina, monitoreando su estado en vivo mediante ddev list -j.

Figura 2.1: Vista general de "Mis Proyectos" mostrando búsqueda reactiva, filtro por tecnología con iconos SVG oficiales, y tarjetas interactivas de proyectos en ejecución, detenidos o pausados.

Funcionalidades Clave

  • Barra de Búsqueda Reactiva: Filtrado instantáneo por nombre de proyecto o tecnología conforme el desarrollador escribe en el campo de entrada.
  • Filtro Desplegable por Tecnología: Selector visual con conteo dinámico e iconos SVG vectoriales oficiales (Drupal, WordPress, Laravel, Django, Next.js, etc.).
  • Control de Proyectos Ocupados (Busy State): Prevención de condiciones de carrera; cuando un proyecto está iniciando o deteniéndose, sus controles se deshabilitan visualmente hasta completar la transacción.
  • Acciones Rápidas con 1 Clic: Iniciar / Detener, Abrir Web (HTTPS en el navegador predeterminado), Terminal (abre la terminal nativa del sistema en el docroot), Carpeta (gestor de archivos con xdg-open), Detalles y Eliminar.
  • Atajos Contextuales Inteligentes: Para sitios Drupal se revelan botones directos hacia el Asistente Drupal y Subsitios.

Figura 3.1: Panel de inspección técnica con runtimes (PHP 8.3 / Nginx), URL principal, servicio webmail Mailpit, conmutador de Xdebug en tiempo real y herramientas universales.

Herramientas y Diagnóstico Avanzado

  • Conmutador de Xdebug en Tiempo Real: Conmutador interactivo ON / OFF que consulta y conmuta el estado de depuración paso a paso (ddev xdebug on / off) sin necesidad de reiniciar los contenedores.

  • Herramientas Universales DDEV: Botones rápidos para inspeccionar logs en vivo (ddev logs -f), abrir consola web interactiva (ddev ssh) o lanzar una terminal en el directorio del proyecto.
  • Exportación e Importación de Base de Datos:
    • Exportar BD: Abre selector nativo de guardado y ejecuta ddev export-db --file=... con compresión .sql.gz en segundo plano.

06 Nuevo Proyecto: Creación Desatendida (11 Tecnologías)

El asistente de creación (NewProjectView) implementa el Patrón Estrategia para orquestar la descarga, configuración de contenedores, aprovisionamiento de dependencias e inicio desatendido de 11 plataformas tecnológicas.

Figura 6.1: Asistente de descarga mostrando la cuadrícula de los 11 frameworks soportados, selectores de motor de base de datos, versiones de runtime y previsualización de ruta.

Matriz de Estrategias Automatizadas

  • Drupal (11, 10, 9, 8, 7): Descarga vía Composer con recommended-project, instalación de Drush, ejecución de drush site:install standard con credenciales admin/admin y soporte multisitio.
  • WordPress: Descarga del core con wp core download y provisión desatendida vía WP-CLI.
  • Laravel: composer create-project laravel/laravel ., generación de .env, configuración de SQLite/MySQL y ejecución forzada de migraciones.
  • Symfony: symfony/skeleton con Composer, instalación de webapp-pack y configuración de variables de entorno.
  • Django & Flask (Python): Creación de virtualenv aislado (.venv), instalación de dependencias, reverse proxy Nginx hacia puerto 8000/5000 y daemon de segundo plano en .ddev/config.daemon.yaml ejecutando runserver.
  • Next.js, Angular, React & Vue (Node.js): Creación con plantillas oficiales TypeScript, configuración de reverse proxy Nginx con soporte WebSockets / HMR en puerto 443 y daemons npm run dev.

07 Nuevo Proyecto: Importación con Detector Heurístico

El modo de importación permite incorporar cualquier código fuente o repositorio existente en el disco duro. El módulo core/detector.py analiza la estructura de archivos e infiere la configuración óptima.

Figura 7.1: Modo de importación con detección automática del stack tecnológico (Drupal 11 con PHP 8.3), deducción del docroot ("web") y validación de nombres seguros.

Lógica de Detección Heurística

  • Proyectos con configuración previa (.ddev/config.yaml): Lee directamente los parámetros existentes (nombre, tipo, docroot, php_version, database, omit_containers) sin alterar la configuración del equipo.
  • Proyectos sin DDEV previo:
    • artisan ➔ Sugiere Laravel, PHP 8.2/8.3 y docroot public.
    • core/lib/Drupal.php ➔ Sugiere Drupal con docroot web o docroot.
    • wp-config.php o wp-load.php ➔ Sugiere WordPress y docroot adecuado.
    • manage.py / requirements.txt ➔ Sugiere Django / Python con Nginx proxy.
    • next.config.* / vite.config.* ➔ Sugiere Next.js, React o Vue con Node.js y proxy WebSocket.

08 Pestaña "Herramientas": Control Global y Estado del Sistema

La pestaña Herramientas (GlobalToolsView) centraliza el mantenimiento y la supervisión del entorno Docker y DDEV en toda la máquina anfitriona.

Figura 8.1: Consola de herramientas globales mostrando controles de parada total, limpieza de cachés, acceso al router Traefik, diagnóstico SSL y reporte de versiones.

Operaciones Administrativas Disponibles

  • Poweroff Global (ddev poweroff): Detiene todos los contenedores DDEV liberando memoria RAM y puertos del sistema.
  • Iniciar Todos (ddev start -a): Reanuda todos los proyectos registrados en bloque.
  • Limpiar DDEV (ddev clean -y): Purga imágenes intermedias de Docker, cachés temporales y archivos residuales.
  • Panel Traefik Router: Abre la consola web de enrutamiento y balanceo en http://127.0.0.1:10999.
  • Detener Contenedores Externos: Detecta y detiene de forma segura contenedores Docker independientes que no pertenecen a DDEV (previo diálogo con lista detallada).
  • Detener TODO en Docker: Ejecuta simultáneamente ddev poweroff y detiene contenedores externos con un único clic.
  • Reporte de Versiones en Vivo: Muestra versiones exactas instaladas de DDEV, Docker Engine, estado de los certificados SSL y ruta raíz (~/sites).

11 Suite Drupal: Generador de Código (Drush Scaffolding)

Para proyectos basados en Drupal (versiones 7 a 11), DDEV Studio ofrece una suite de herramientas de nivel arquitectónico (ui/views/drupal_tools.py) que automatiza la generación de esqueletos de código limpio cumpliendo los estándares de la comunidad.

Figura 11.1: Formulario interactivo para generar módulos custom, controladores (ControllerBase), formularios y plugins REST sin escribir archivos boilerplate a mano.

Componentes Generables Asistidos

  • Módulo Personalizado (.info.yml): Genera la estructura básica en modules/custom/<nombre> con archivos .info.yml, .module y permisos.
  • Controlador (ControllerBase): Esqueleto de controlador PHP con inyección de dependencias, definición de rutas en .routing.yml y retorno de render arrays.
  • Formulario (FormBase): Formulario estructurado con métodos getFormId(), buildForm(), validateForm() y submitForm().
  • Servicio Symfony (.services.yml): Registro de clase de servicio en el contenedor de inyección de dependencias de Drupal.
  • Plugin REST Resource (@RestResource): Endpoint API REST nativo con métodos GET, POST, PATCH y DELETE autenticados.

14 Gestor de Drupal Multisitio Nativo

La vista SubsitesManagerView administra arquitecturas donde un único codebase central de Drupal sirve a múltiples dominios independientes con sus propias bases de datos y configuraciones aisladas en sites/<subsitio>.

Figura 14.1: Panel de Drupal Multisitio mostrando subsitios detectados (portal-tienda, portal-blog), sincronización de dominios en DDEV y bases de datos independientes.

Sincronización Atómica y Automatización

  • Sincronización de FQDNs en DDEV: Al agregar un nuevo subsitio (ej. tienda), DDEV Studio actualiza de forma atómica additional_fqdns en .ddev/config.yaml, habilitando https://tienda.ddev.site.
  • Inyección en sites.php: Configura y mantiene el mapeo de dominios en sites/sites.php para que Drupal resuelva la carpeta correcta según el host entrante.
  • Bases de Datos Aisladas: Cada subsitio cuenta con su propia base de datos dedicada (db_subsitio) sin colisionar con el sitio principal.
  • Contexto Drush por Subsitio: Todos los comandos de limpieza de caché o ejecución de scripts respetan el parámetro contextual --uri=https://<subsitio>.ddev.site.

17 Diagnóstico y Reparación de Certificados SSL (mkcert)

Uno de los dolores de cabeza más comunes en el desarrollo web local con HTTPS es el error del navegador NET::ERR_CERT_AUTHORITY_INVALID ("La conexión no es privada"). El diálogo modal SSLDiagDialog provee un diagnóstico paso a paso y solución asistida en 1 clic.

Figura 17.1: Diagnóstico del estado de mkcert, certutil (libnss3-tools) y el almacén de autoridades de confianza en Chrome, Chromium y Firefox.

Protocolo de Verificación del Diálogo

  1. Detección de mkcert: Verifica si la utilidad mkcert está disponible en el PATH del sistema (ej. /usr/local/bin/mkcert).
  2. Detección de libnss3-tools (certutil): Comprueba si la herramienta de gestión de certificados NSS está instalada para permitir que Chrome y Firefox reconozcan la autoridad raíz. Si no está instalada, ofrece un botón para instalar el paquete del sistema operativo.
  3. Registro de Autoridad Raíz Local: Ejecuta mkcert -install en segundo plano para registrar el certificado de DDEV en los almacenes locales del navegador, resolviendo el candado verde HTTPS de forma permanente.

18 Automatización CI/CD con GitHub Actions

Para proyectos con repositorio Git (.git), CIDialog (core/ci_templates.py) detecta la tecnología en uso y genera workflows de GitHub Actions probados en contenedor con matrices de compatibilidad.

Estructura del Flujo de Trabajo Generado

El archivo .github/workflows/ddev-ci.yml incluye:

19 Desinstalación Segura de Módulos (CLI vs Web Asistida)

En Drupal, desinstalar un módulo que posee dependencias activas puede romper la base de datos o el contenedor de dependencias. Para prevenir esto, DDEV Studio implementa el diálogo modal inteligente DrupalUninstallDialog.

Figura 19.1: Diálogo con flujo dual de desinstalación: Vía CLI directa con Drush o vía Web asistida con salto directo al ancla del módulo en Drupal.

Flujo Dual de Desinstalación

  • Vía 1: Desinstalación Directa con Drush CLI: Ejecuta drush pm:uninstall <modulo> -y seguido de drush cr en segundo plano con control de errores. Si el módulo tiene dependencias bloqueantes, captura la salida y ofrece abrir la vía web.
  • Vía 2: Vía Web Asistida en Drupal: Abre el navegador predeterminado en la URL exacta de desinstalación (/admin/modules/uninstall#edit-uninstall-<modulo>), permitiendo al desarrollador revisar en pantalla qué tablas o campos serán eliminados.
